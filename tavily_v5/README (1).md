# tavily_v5 (v5.0) — 박람회 준비 데스크 리서치

해외시장조사 담당자의 데스크 리서치 방식을 옮긴 도구입니다.
제품과 국가를 입력하면 4가지 조사 질문에 대해 웹 원문을 찾아 **문장 그대로 발췌**하고,
원문에서 확인된 발췌만으로 AI가 요약합니다.

> 원칙: **AI는 사실을 쓰지 않는다. 원문에서 찾아 붙이고, 정리만 한다.**
> **AI의 판단(국가·제품 관련성)은 코드 신호로 한 번 더 확인한다.**

결과가 이상할 때는 [9. 오류 추적 가이드](#9-오류-추적-가이드)부터 보세요.
지금까지 어떤 결과 때문에 무엇을 고쳤는지는 [11. 수정 이력](#11-수정-이력)의 사례 목록에 있습니다.
코드를 고친 뒤에는 [8. 평가 세트 3×3](#8-평가-세트-33)을 돌려 규칙이 새지 않는지 확인하세요.

## 1. 설치와 실행

```bash
cd tavily_v5
python -m venv .venv
.venv\Scripts\activate            # Mac/Linux: source .venv/bin/activate
pip install -r requirements.txt

python app.py                     # 웹 화면: http://127.0.0.1:5051
python cli.py --product 김부각 --country Germany
python cli.py --product 김부각 --country Germany --exhibition ANUGA --website anuga.com --strengths "찹쌀 코팅 수작업"
python cli.py --product 김부각 --country Germany --debug      # 쿼리, 제외 출처, 지운 요약 문장까지 출력
python cli.py --product 김부각 --country Germany --audit 10   # 발췌 무작위 점검
python eval/run_eval.py                                       # 평가 세트 3×3
```

- `.env`는 저장소 최상위(`SABUZAK/.env`)를 자동으로 찾아 씁니다. 필요한 키: `OPENAI_API_KEY`, `TAVILY_API_KEY`.
  실행하면 첫 줄에 사용 중인 `.env` 경로가 출력됩니다. `.env` 값이 OS 환경변수보다 우선합니다.
- 웹 화면은 **5051 포트**입니다 (v3가 5050을 쓰는 경우가 있어 분리). 페이지 제목이 "박람회 준비 데스크 리서치"이고
  상단에 `v5.0`이 보이면 이 버전입니다.

## 2. 동작 흐름

모든 로직은 `research.py`에 있고, 외부에서는 `run_research()`만 호출합니다.

| 단계 | 함수 | 하는 일 | 판단 주체 |
|---|---|---|---|
| 1. 용어 준비 | `prepare_terms()` | 제품 용어(현지어·영어·로마자), 제품군 용어, 한국 식품 용어, 국가 이름들, 현지어 검색 단어, 권역 준비 → 제품 용어는 검색 결과 본문에 실제로 2건 이상 등장해야 채택, 좁은 용어부터 최대 2개 | AI 제안, 코드 검증 |
| 2. 쿼리 | `build_queries()` | 질문별 고정 템플릿 + 한국 공공기관(KOTRA·aT KATI) 한국어 쿼리 + 박람회 쿼리. 권역은 국가별로 넣고, 중복 쿼리 제거 | 코드 |
| 3. 검색 | `collect_sources()`, `_search()`, `clean_body()` | Tavily 검색(보고서 판매 사이트·SNS는 검색 단계와 결과 단계에서 이중 제외). 원문에서 메뉴·관련 글·댓글 등 본문 외 영역 제거 | 코드 |
| 4. 발췌 | `extract_quotes()` | AI가 출처마다 시장(`country` / `region` / `other`)을 표시하고, 원문 문장을 그대로 발췌·번역 | AI |
| 5. 검사 | `verify_quotes()`, `classify_market()`, `quote_scope()` | 원문 글자 대조, 시장 판정 확인, 발췌 범위 판정, 자료 연도, 번역 숫자 확인 | 코드 |
| 6. 요약 | `summarize_question()`, `_check()` | 확인된 발췌만 근거로 결론·핵심 사실·AI 해석 작성 → 코드가 문장별로 검사하고 실패한 문장은 사유와 함께 기록 | AI 작성, 코드 검사 |
| 7. 부스 기획 | `plan_booth()` | 요약 결과 + 기업 제품 정보로 핵심 메시지·근거·아이디어 제안 (같은 검사 적용) | AI 제안, 코드 검사 |

## 3. 코드가 강제하는 규칙

### 3-1. 출처 단계

| 규칙 | 위치 | 내용 |
|---|---|---|
| 보고서 판매 사이트 제외 | `source_quality()`, `REPORT_SELLER_DOMAINS`, `REPORT_SELLER_PATTERN` | factmr, wiseguyreports, grandviewresearch 등 유료 보고서 홍보 페이지. 도메인 목록 + 이름 패턴(`market-research`, `market-report` 등) |
| SNS 제외 | `SOCIAL_DOMAINS` | facebook, instagram, tiktok, linkedin, x, youtube, lemon8 등 |
| 본문 외 영역 제거 | `clean_body()` | "Related posts", "Kommentare", "関連記事", "관련기사" 등이 나오면 그 뒤를 자르고, 40자 미만 줄(메뉴·링크)은 뺌 |
| 한국 공공기관 | `KR_PUBLIC_DOMAINS` | KOTRA·aT KATI 도메인만 한국어로 검색, 발췌에 "한국 공공기관" 배지 |

### 3-2. 발췌 단계

| 규칙 | 위치 | 내용 |
|---|---|---|
| 원문 대조 | `verify_quotes()` | 정규화(따옴표·대시·공백·대소문자) 후 **본문 영역**에 글자 그대로 있어야 통과. 20~350자 |
| 시장 판정 | `classify_market()` | **대상 국가**: AI가 country로 표시 + (도메인 국가코드가 대상 국가 또는 제목·본문에 대상 국가명 언급 또는 박람회명 언급). **권역 참고**: AI가 country/region 표시 + (권역 표현 언급 또는 같은 권역 국가 도메인). 그 외는 **다른 시장**으로 제외 |
| 권역 결정 | `COUNTRIES`, `REGIONS` | 국가 → 권역 표 (북미, 유럽, 동아시아, 동남아시아, 남아시아, 중동, 오세아니아, 중남미, 아프리카). 표에 없는 국가는 AI가 제안한 권역 사용 |
| 발췌 범위 | `quote_scope()` | 발췌 **원문**(번역 아님)에 제품 용어가 있으면 `제품`, 제품군 용어면 `제품군`, 한국 식품 표현이면 `한국 식품`, 없으면 `시장 일반` |
| 질문별 허용 범위 | `ALLOWED_SCOPES` | Q1 소비자·Q2 경쟁 제품은 `시장 일반` 발췌 불가. Q3·Q4는 허용 |
| 자료 연도 | `source_year()` | 검색 결과 날짜 → URL 속 연도 순으로 찾음. 조사 시점보다 3년 이상 지나면 `오래된 자료` |
| 번역 숫자 | `verify_quotes()` | 번역에 원문에 없는 숫자가 있으면 `번역 확인 필요` 배지. 유럽식 소수점(2,49)은 2.49로 맞춰 비교 |

### 3-3. 요약 단계 (`_check()`)

요약 문장마다 아래를 검사하고, 실패한 문장은 지운 뒤 사유를 `dropped`에 남깁니다. 화면에서 "검사에서 지운 요약 문장"을 펼치면 볼 수 있습니다.

| 사유 | 조건 |
|---|---|
| 근거 없음 | 근거 발췌 id가 없거나 존재하지 않음 |
| 근거에 없는 숫자 | 문장 속 숫자가 근거 발췌 **원문**에 없음 (번역문 숫자는 인정하지 않음) |
| 제품 근거 없이 제품명 사용 | 문장에 제품명이 있는데 근거 중 `제품` 발췌가 없음 |
| 권역 자료를 국가 자료처럼 서술 | 근거가 모두 `권역 참고`인데 문장에 권역명(예: 유럽)이 없음 |
| 결론: 오래된 자료만 근거 | 결론의 근거가 모두 `오래된 자료` (결론에만 적용) |

결론이 검사에서 지워지면, 오래되지 않은 자료를 근거로 한 첫 번째 핵심 사실로 대체합니다.

### 3-4. AI 판단에 남아 있는 것

코드 검사로 줄였지만 완전히 없앨 수 없는 부분입니다.

- 출처 시장 표시의 1차 판단 (코드는 국가명 언급·도메인으로 확인만 함)
- 발췌 문장 선택, 번역의 뉘앙스, 요약의 표현
- 잡담·서사 배제 (프롬프트 규칙 + 본문 외 영역 제거로 줄임)

## 4. 조사 질문과 쿼리

| | 질문 | 제품 용어 쿼리 | 보조 쿼리 |
|---|---|---|---|
| Q1 소비자 | 현지 소비자는 이 제품군을 언제, 왜 먹고, 무엇에 불만이 있는가 | `{제품 용어} {후기}`, `{제품 용어} {트렌드} {국가}` | `{한국 식품} {트렌드} {국가}` |
| Q2 경쟁 제품 | 경쟁 제품은 무엇이고, 얼마에, 어떤 메시지로 파는가 | `{제품 용어} {브랜드} {가격} {국가}` | `{제품군} {브랜드} {국가}` |
| Q3 바이어·유통 | 바이어·유통사는 무엇을 보고 제품을 들여오는가 | `{제품 용어} {수입·유통업체} {국가}` | `{한국 식품} {수입·유통업체} {국가}` |
| Q4 박람회·부스 | 박람회 트렌드와 부스 운영·시식 사례 | 박람회명 입력 시 `{박람회명} {제품군} trends`(공식 사이트 한정), `{박람회명} {부스} exhibitors` | 미입력 시 `food trade show {제품군} booth sampling {권역}` |
| 공공기관 | (질문은 발췌 시 AI가 배정) | `{국가 한국어명} {제품명}` | `{국가 한국어명} {제품군 한국어} 시장 동향` |

`{후기}`, `{트렌드}` 등은 현지어 검색 단어(예: 독일이면 Test, Trend, Preis)이고, `{국가}`는 현지어 국가명(예: Deutschland)입니다.
실제 실행된 쿼리는 `python cli.py ... --debug` 또는 결과 데이터의 `queries`에서 확인합니다.

## 6. 결과 데이터 구조 (요약)

```
run_research() 반환값
├── terms            용어 준비 결과 (selected, product_match, country_names, region_ko, tld ...)
├── queries          실행한 쿼리 목록
├── cards[]          질문별 카드: conclusion, points, interpretation, gaps, notice,
│                    quote_ids, product_quotes, country_quotes, diagnostics, dropped[{text, reason}]
├── booth            key_message, reasons, ideas, dropped, has_profile, has_product_evidence
├── quotes[]         id, question, quote, translation_ko, translation_warning, scope, market,
│                    market_label, year, is_stale, is_public_kr, source_ids
├── sources[]        id, title, url, domain, published_date, year, market, is_public_kr, found_by
├── excluded_sources[] url, domain, reason (보고서 판매 사이트 / SNS)
└── stats            sources_found, quotes_used, excluded_source, market_other, not_in_source,
                     off_scope, country_quotes, region_quotes, stale_quotes, translation_warnings
```

리포트는 `research_cache.db`의 `report_cache` 테이블에 JSON으로 저장됩니다.

## 8. 평가 세트 3×3

코드를 고친 뒤 **같은 9개 조합**을 돌려, 거르는 규칙이 조건별로 제대로 작동하는지 숫자로 확인합니다.
식품 정보가 맞는지를 식품마다 검증하는 것이 아니라, **프로그램 규칙을 점검**하는 도구입니다.
평소 사용할 때는 돌리지 않고, 코드를 수정했을 때만 돌립니다.

| | 미국 (영어권, 북미) | 독일 (비영어권, 유럽) | 일본 (아시아, 한국 식품 친숙) |
|---|---|---|---|
| 김부각 (해외에서 낯선 틈새 제품) | 1 | 2 | 3 |
| 소금빵 (나라마다 이름이 다른 제품) | 4 | 5 | 6 |
| 비건 만두 (자료가 많은 인기 제품군) | 7 | 8 | 9 |

```bash
python eval/run_eval.py                                   # 9개 실행 (캐시 있으면 재사용)
python eval/run_eval.py --force                           # 새로 조사 (코드 수정 후 권장, API 비용 발생)
python eval/run_eval.py --only 김부각:Germany 소금빵:Japan
python eval/run_eval.py --force --compare eval/results/20260922_1030.csv   # 이전 결과와 비교
```

결과는 `eval/results/<시각>.csv`(숫자)와 `<시각>.md`(표 + 사람이 확인할 발췌 샘플 5개씩)로 저장됩니다.

| 자동 집계 항목 | 기대값 | 0이 아니면 |
|---|---|---|
| 근거로 쓰인 보고서 사이트·SNS | 0 | `source_quality()` 목록·패턴 누락 |
| 다른 권역 이름이 들어간 쿼리 | 0 | 쿼리 템플릿에 권역 하드코딩 재발 (K2) |
| 다른 나라 도메인인데 '대상 국가'로 판정된 발췌 | 낮을수록 | 해당 발췌를 열어 확인. 본문에 대상 국가명이 있으면 정상일 수 있음 |
| Q1·Q2의 제품 발췌 | 높을수록 | 0이면 제품 용어 검증(K6)이나 현지어 쿼리 확인 |
| 발췌 2건 미만인 질문 | 참고 | 정보량이 줄었는지 확인 (엄격해진 대가) |
| 오래된 자료 발췌, 번역 숫자 불일치, 지운 요약 문장 | 참고 | 급증하면 원인 확인 |

사람은 `.md` 파일에서 숫자가 이상한 조합만 발췌 샘플을 열어 `맞음 / 제품 무관 / 다른 시장 / 번역 오류 / 요약 일반화`로 표시합니다.

## 9. 오류 추적 가이드

| 증상 | 먼저 볼 것 | 가능한 원인과 위치 |
|---|---|---|
| 다른 나라 자료가 나옴 | 발췌의 시장 배지, 하단 출처 목록의 시장 판정 | `권역 참고`면 정상(대상 국가 자료 아님). `대상 국가`인데 다른 나라면 `classify_market()` — 본문에 대상 국가명이 우연히 언급됐을 가능성 |
| 제품과 무관한 문장이 제품 근거로 나옴 | 발췌의 범위 배지 | `제품` 배지인데 무관하면 `prepare_terms()`의 `product_match`에 너무 넓은 용어가 들어감 (`--debug`로 용어 확인) |
| 요약이 발췌보다 일반화됨 | "검사에서 지운 요약 문장" | 검사를 통과한 일반화는 3-4의 AI 판단 영역. `summarize_question()` 프롬프트 규칙 2 확인 |
| 보고서 판매 사이트·SNS가 보임 | 도메인 | `REPORT_SELLER_DOMAINS`, `SOCIAL_DOMAINS`에 추가 |
| 메뉴·관련 글 문장이 발췌됨 | 원문 링크에서 해당 문장 위치 | `BOILERPLATE_MARKERS`에 그 사이트의 표시 문구 추가 |
| 정보가 거의 안 나옴 | 상단 통계의 제외 건수, 카드 하단 진단 | "다른 시장"이 많으면 국가 판정이 엄격한 것, "범위 밖"이 많으면 제품 용어가 좁은 것, "원문에 없음"이 많으면 AI가 발췌를 바꿔 씀. 틈새 품목은 자료 자체가 적을 수 있음 |
| 제품 용어가 "확인된 용어 없음" | `--debug`의 용어 확인 결과 | 현지에서 쓰는 이름이 AI 후보에 없음. `TERM_MIN_HITS` 또는 프롬프트 확인 |
| 같은 입력인데 결과가 다름 | `force` 사용 여부, `VERSION` | AI 판단이 실행마다 다름. 캐시 결과로 비교 |
| v3·v4 화면이 뜸 | 페이지 제목, 상단 버전 | 다른 터미널의 이전 서버. 모두 `Ctrl + C` 후 v5 폴더에서 재실행 |
| "조사 중 오류가 발생했습니다" | 서버 터미널의 traceback | API 키, 네트워크, Tavily 파라미터(`exclude_domains` 등) 미지원 SDK |
| 코드를 고쳤는데 결과가 그대로 | `VERSION` | 리포트 캐시. `VERSION`을 올리거나 "캐시 무시하고 새로 조사" |

## 10. 캐시와 비용

- 검색 결과는 쿼리 단위(`search_cache`), 조사 결과는 입력 단위(`report_cache`)로 30일 저장.
- `VERSION`을 올리면 조사 결과 캐시만 무효화되고 검색 캐시는 재사용됩니다. v5는 본문 정리 방식이 바뀌어 검색 캐시 키도 새로 만듭니다.
- 검색 캐시에는 정리된 원문 일부(최대 6,000자)가 저장되니 외부에 공유하지 마세요.
- 비용(1회, 대략): Tavily 용어 확인 basic 최대 4회 + 검색 advanced 약 10~13회, OpenAI 용어 1회 + 발췌 약 6~10회 + 요약 4회 + 부스 1회.
  평가 세트 `--force`는 이 비용의 9배입니다. 개발 중에는 `SEARCH_DEPTH`를 `"basic"`으로 바꾸세요.

### 제미나이 대화에서 나온 제안과 반영 여부

`tavily_수정과정.txt`에 기록된 제안입니다. v5.0에 어떻게 반영했는지, 반영하지 않았다면 이유를 적었습니다.

| 제안 | v5.0 반영 | 내용 |
|---|---|---|
| OpenAI 단독 사용으로 전환 | **미채택** | 자체 지식·브라우징에 의존하면 출처와 최신성이 불안정함. Tavily가 원문·URL을 가져오고 OpenAI가 판단하는 하이브리드 구조를 유지 |
| 2단계 검증 (Tavily 수집 → OpenAI 의미 판정) | **반영 (방향 조정)** | AI가 출처 시장과 발췌를 판정하고, 그 결과를 코드가 문자열·도메인 신호로 다시 확인하는 구조. 다만 문자열 대조(`_norm`)는 없애지 않고 유지함 — 발췌가 원문에 실제로 있다는 보장은 AI 판단으로 대체할 수 없기 때문 |
| 판정 이유(reasoning) 출력 | **미반영** | 이유 문장이 늘면 검토 비용이 커지고, 이유 자체도 AI 생성물이라 검증이 안 됨. 대신 코드가 판정 근거(도메인 국가코드·국가명 언급·용어 일치)를 배지와 진단 숫자로 남김 |
| 의미론적 동의어 확장 맵 | **반영** | `prepare_terms()`가 현지어·영어·로마자 표기를 함께 생성하고, 검색에는 검증된 용어를, 발췌 범위 판정에는 후보 전체(`product_match`)를 사용해 누락을 줄임 |
| `product_specific` / `category_general` 태깅 | **반영 (강화)** | AI 태그 대신 코드가 발췌 원문의 용어로 `제품 / 제품군 / 한국 식품 / 시장 일반`을 판정. AI가 임의 값을 넣어도 영향받지 않음 |
| 제품 발췌 0건이면 그 사실을 명시 | **반영** | Q1·Q2에서 대상 국가의 제품 발췌가 0건이면 카드 상단에 경고를 띄우고, 요약에서 제품명을 쓴 문장은 코드가 삭제 |
| 국가 AND 제품 강제 | **반영 (3단계로 완화)** | 완전한 AND는 자료가 사라지는 문제가 있어(사례 4), 대상 국가·권역 참고·다른 시장으로 나누고 권역 자료는 범위를 밝혀 쓰도록 검사 |
| 뉴스 요약 규칙 설정 | **반영** | 발췌·요약 프롬프트의 노이즈 규칙 + 본문 외 영역 제거 + "발췌 하나를 소비자 전체로 일반화하지 말 것" 규칙 |

### 아직 반영하지 않은 설계안

| 설계안 | 상태 | 비고 |
|---|---|---|
| 단계적 확장 검색 (제품 → 제품군 → 한국 식품 → 인근 시장 순으로 부족한 질문만 재검색) | 미반영 | 현재는 처음부터 제품·제품군·한국 식품 쿼리를 함께 돌리고 권역 자료를 배지로 구분하는 방식. 자료 부족이 계속되면 추가 검토 |
| 자료를 못 찾은 질문에 현장 확인 체크리스트 제공 (바이어 질문, 무역관 문의, 매장 확인) | 미반영 | 현재는 "확인 필요" 문구만 표시 |
| 무역 통계(관세청·UN Comtrade) 연동으로 성장률 확보 | 미반영 | 웹 기사 수치 대신 기준이 명확한 정량 데이터를 쓰려면 별도 작업 필요 |
| 전 식품군 서비스화 (카테고리 체계, 기업별 계정, 공용 캐시) | 미반영 | 구조 설계만 논의됨. 현재는 단일 폴더 도구 |

기록에서 확인되는 점:
- **"대상 외 자료"가 모든 실행에서 0건**입니다. 국가 판정(`usable`)이 사실상 아무것도 거르지 못하고 있습니다.
- 김부각 × 독일(v4.1)의 사용 출처에 myfreshdash.com, pulse.mk.co.kr(한국 언론), usatradeshowshipping.com 등이 포함되어 있습니다.
- 비건 만두 × 독일(v4.4)의 사용 출처에도 walmart.com(미국), pulmuone.co.kr(한국 기업), tripadvisor.com 등이 포함되어 있습니다.
- v4.4에서 버린 발췌가 늘어난 것(11~13건)은 노이즈 배제 규칙이 작동한 영향으로 보입니다. 같은 입력인데 Q4 발췌가 0건과 2건으로 달라, 결과 재현성이 낮습니다.
- `relevance_type` 값이 `product_specific`, `consumer_insight`, `buyer_distribution`, `market_trend` 등 AI가 임의로 만든 값으로 들어옵니다.

v4.x 기록에서 "대상 외 자료"가 모든 실행에서 0건이었고, 사용 출처에 myfreshdash.com, walmart.com, pulmuone.co.kr, 보고서 판매 사이트, SNS가 섞여 있었습니다. v5.0은 이 기록을 기준으로 K1~K18을 정리해 반영했습니다.
v5.0의 실제 결과는 `eval/results/`에 쌓이는 평가 세트 결과로 확인하세요.

## 12. v5.0에 남은 한계

| 한계 | 내용 | 확인 방법 |
|---|---|---|
| 실제 API로 검증 전 | 가짜 응답으로 규칙 동작만 확인함 (다른 시장 제외, 보고서·SNS 제외, 본문 외 영역 제거, 범위 판정, 주어·권역 검사, 오래된 자료 결론 대체, 번역 숫자 표시, 미국 쿼리의 북미 권역) | 첫 실행 후 `python eval/run_eval.py --force` |
| 국가명 언급 기준 | 다른 나라 글이 대상 국가를 한 번 언급해도 `대상 국가`가 될 수 있음. 반대로 국가명을 안 쓰는 현지 글(.com 도메인)은 제외될 수 있음 | 평가 세트의 "다른 나라 도메인인데 대상 국가" 항목 |
| 보고서 판매 사이트 목록 | 목록·패턴에 없는 사이트는 통과 | 발견 시 `REPORT_SELLER_DOMAINS`에 추가 |
| 본문 외 영역 제거 | 사이트마다 구조가 달라 표시 문구가 없는 관련 글 영역은 남을 수 있음 | `BOILERPLATE_MARKERS`에 추가 |
| 날짜 | 검색 결과와 URL에 연도가 없으면 오래된 자료인지 판단 못 함 ("연도 미상") | 배지 확인 |
| 카드 하단 진단 | 같은 출처가 여러 쿼리에서 나오면 처음 찾은 질문에만 집계됨 | 전체 합계는 상단 통계 기준 |
| Tavily 파라미터 | `exclude_domains`, `include_raw_content`, `time_range` 지원 여부는 SDK 버전에 따라 다를 수 있음 | 오류 시 `pip install -U tavily-python` |
| 한국 공공기관 검색 | Tavily가 KOTRA·aT KATI 페이지를 얼마나 수집했는지에 따라 결과가 없을 수 있음 | 발췌의 `한국 공공기관` 배지 유무 |

```
tavily_v5/
├── app.py                  # 웹 화면 (5051 포트)
├── cli.py                  # 터미널 실행 (--debug, --audit)
```

`research_cache.db`, `__pycache__/`, `*.pyc`는 커밋하지 않습니다. 평가 결과(`eval/results/*.csv`, `*.md`)는
수정 전후 비교 기록이므로 커밋해 두면 나중에 원인 추적에 도움이 됩니다.
